왜 Agent인가02

좋은 문장이 아니라 작업의 완결성이 목표다

Chatbot

질문에 답한다
주어진 context 안에서 추론한다
대화가 끝나면 작업도 끝난다

Agent

목표를 받아 행동한다
도구로 자료·코드·환경을 사용한다
결과를 관찰하고 수정하며 완료한다
핵심 질문: “무엇을 말했는가?”보다 “무엇을 완료했고 어떻게 검증했는가?”
학습 목표03

수업이 끝나면 네 가지를 할 수 있어야 한다

1. 구조를 설명한다

Model, tool, memory, skill, profile, subagent를 구분한다.

2. 연구를 실행한다

공식 자료 수집부터 계산·보고서까지 한 workflow로 연결한다.

3. 분업을 설계한다

전문 agent의 비교우위와 검증 책임을 배치한다.

4. 실패를 판정한다

오류·편향·권한·재현성 문제를 evidence로 감사한다.

Agent Loop04

Agent loop가 모든 기능의 중심이다

목표
추론
도구 실행
결과 관찰
검증·수정
목표: “한국은행의 최근 금리결정을 분석하라”를 검증 가능한 완료 조건으로 바꾼다.
Agent는 한 번의 추론이 아니라, 관찰을 받아 반복하는 control loop다.
Hermes Architecture05

Hermes는 모델 위에 실행 구조를 더한다

Channels · CLI, Desktop, messaging, gateway
Agent Core · context, reasoning, tool loop, session
Capabilities · tools, skills, plugins, MCP, delegation
Execution Environment · local, container, remote system

모델을 바꿔도 workflow 구조는 유지된다. 따라서 “어떤 모델인가”와 “어떤 agent system인가”를 분리해서 평가해야 한다.

Evidence Discipline08

경제분석은 해석보다 Evidence가 먼저다

자료의 정체성

기관·문서·발표시점·버전·URL

내용의 무결성

원문·파일 hash·추출 위치

판단의 연결

어떤 수치와 문장이 어떤 결론을 지지하는가

Evidence packet

{
  "as_of": "2026-08-13",
  "source": "official",
  "document_id": "...",
  "content_hash": "sha256:...",
  "claim_refs": ["p.3", "table-2"]
}
Agent가 찾아왔다는 사실은 근거가 아니다. identity와 content가 묶여야 한다.
Reproducibility09

재현성은 금융 Agent의 최소 계약이다

As-of
Data snapshot
Code version
Output digest
Receipt

같은 입력

동일한 시점과 동일한 데이터가 보존된다.

같은 계산

결과가 일치하거나 차이가 명시적으로 설명된다.

“오늘 다시 돌려도 된다”와 “과거 시점 판단을 재구성할 수 있다”는 다르다.
Memory vs Skill10

Memory와 Skill은 저장하는 대상이 다르다

Session

이번 대화에서 진행된 작업 맥락

Memory

작고 오래 유지할 사실·선호·환경 정보

Procedural Memory11

좋은 Skill은 조직의 반복 가능한 Routine이다

Skill에 들어갈 것

  • 업무의 trigger와 완료 조건
  • 공식 data route와 검증 방법
  • 실패 유형과 복구 순서
  • 출력 schema와 예시

Skill이 아닌 것

  • 한 번의 대화 전문
  • 특정 시점의 시장 전망
  • API 연결 자체
  • 검증되지 않은 성공담
경제학적 대응: Nelson–Winter의 organizational routine · 출처 [3]
Integration12

Tool, MCP, Plugin은 행동 경로를 만든다

Tool

Agent가 호출할 수 있는 한 가지 행동

예: 파일 읽기, Python 실행

MCP

외부 system의 tools를 표준 방식으로 노출

예: DB·문서·업무 시스템

Plugin

tools·hooks·commands·skills를 하나의 확장으로 묶음

예: 금융데이터 provider package

Skill은 “어떻게 일할 것인가”이고, MCP/Plugin은 “어디에 접근하고 무엇을 실행할 수 있는가”이다.

parent context 비용 절감

비용

Governance18

금융 Agent의 권한은 결과의 중대성에 맞춘다

조건부 승인

외부 발송, canonical 반영, scheduler 변경

인간 결정
